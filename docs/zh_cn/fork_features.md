# 本分支独有功能

上游的功能请看[用户手册](./user_guide.md)。本页只讲 JLLabelingAndTrain 自己加的东西
——它们在上游的文档里当然找不到，而此前只散落在 `CHANGELOG.md` 里，那份是给开发者看的。

> 界面语言只有中文。本分支的文案是直接用中文写在源码里的，不是翻译过来的，
> 所以本页也只写中文。

## 1. 项目管理

一个「项目」就是一次打开图片文件夹所建立的记录：图片目录、标注目录、标签列表、
训练偏好、划分种子。它保存在图片文件夹下的 `.jllabel/project.json`，
因此**项目跟着数据走**，换机器、换分支都不会丢。项目索引在
`<工作目录>/.jllabel/projects.json`（最多 20 条，已消失的目录会被跳过）。

| 操作 | 入口 |
|---|---|
| 切换项目 | `文件 → 切换项目`，快捷键 `Ctrl+Shift+O` |
| 启动行为 | 上次的会话直接恢复（目录 + 上次那张图）；有记录但没有会话时打开项目管理器；首次运行保持空白画布 |
| 每次启动都显示管理器 | 项目管理器里的「启动时显示项目管理」勾选框（对应配置项 `startup_show_project_manager`，默认关闭） |
| 打开设置文件夹 | 项目管理器 →「打开项目设置文件夹」 |
| 清空本项目设置 | 项目管理器 →「重置本项目设置」（**保留**划分种子，训练/验证集划分不受影响） |
| 不再显示某个项目 | 项目管理器 →「从列表移除」 |

项目管理器有四列：项目、上次打开、训练、最近训练。后两列来自每次训练留下的
`run_meta.json`，按路径前缀与项目匹配——所以 `plates` 和 `plates_extra`
这种同前缀的兄弟目录不会互相记账。

### 每个项目有自己的设置

标签建议列表和标注输出目录都记在项目里，文件夹 B 不会再继承文件夹 A 的配置。
被记录的目录若已不存在会被忽略，而不是清空。

设置页里有一类「训练调参」也会跟着项目走（白名单：`basic.model`、`basic.pose_config`
以及八个纯超参段落）。刻意**不**跟随项目的项：`basic.project`（全局 runs 根目录）、
`basic.name`（run 名）、`basic.data`（每次重建的临时数据集 yaml）、`basic.device`、
`train.workers`（与机器绑定）、`basic.dataset_ratio`（数据划分选择，不是调参）。

同时开两个实例时，工具会按工作目录识别并在日志里记一行：项目设置互相隔离，
但全局配置（rc）与最近列表仍是「后关闭者胜」。

## 2. 标注工作流与检查状态

每张图有一个检查状态，记在标注文件里：

| 状态 | 含义 |
|---|---|
| 未检查 | 默认 |
| 已确认 | 人工确认无误 |
| 需返工 | 标记为待修正 |

| 操作 | 入口 |
|---|---|
| 标记已检查并下一张 | 快捷键见 F1（「检查完成并下一张」） |
| 标为需返工并下一张 | `Ctrl+Shift+K` |
| 只看需返工 | 文件列表上方的筛选下拉框选「需返工」 |
| 整体进度 | 状态栏：`已标 a/b · 已检查 c · 待复核 d · 需返工 e` |

「需返工」还有一个按阈值的用法：筛选下拉框里那一条的提示写明了它是
「含有未达自动接受阈值目标的图片；阈值可由「阈值校准」生成」——
先用智能工具里的阈值校准跑一次，这个筛选才有意义。

## 3. 智能工具

`智能工具` 菜单下有 11 项，**建议按编号顺序用**：

| # | 工具 | 作用 |
|---|---|---|
| 1 | 阈值校准 | 按各类置信度分布生成「自动接受 / 建议复核」阈值 |
| 2 | 数据智能分析 | 难例排序、疑似重复图片、类别配平建议 |
| 3 | 漏标扫描 | 用当前模型找出置信度高但没有标注的目标 |
| 4 | 迭代看板 | 每轮「训练 → 回灌」的边际收益与下一步建议 |
| 5 | 智能复核 | 跳到下一张待复核图片 |
| 6 | 标注传播 | 把上一张已标注图片的框按比例复制到当前图，自动跳过重复框 |
| 7 | 一键去重归档 | 把近重复图片及其标注移到 `._duplicates_archive/` |
| 8 | 训练建议 | 训练前预检，并按当前数据与历史轮次推荐 `epochs`/`batch`/`imgsz` 初值 |
| 9 | 智能模板预标注（批量） | 用模板对整批图片预标注 |
| 10 | 旧轮模型框盘点 | 列出由其它模型留下、可考虑清理的框（**只报告，不删除**） |
| 11 | 从备份恢复标注 | 列出 `.label_backups/` 下的快照并写回，**替换前会先备份**，所以选错也能退回 |

三处安全约定值得记住：

- **第 7 项**把文件移到 `._duplicates_archive/`，不是删除。
- **第 10 项**只报告。已锁定、无来源、以及事后被编辑过的框永远不会被列入删除。
- **第 11 项**恢复前会先把当前标注快照到 `.label_backups/<时间戳>/`，
  两秒内做两次快照也不会互相覆盖。画布上那张有未保存改动的图片会被跳过。

## 4. 训练与迭代

- 从标注界面可以直接进入训练（Ultralytics 训练平台），训练期间可继续标注。
- 每次跑完训练都会写 `run_meta.json`：权重哈希、完整参数、数据集 manifest 哈希、指标。
- 数据集会写 `manifest.json`：每张图的内容哈希、划分归属、类别、随机种子。
  划分种子固定在项目的 `.jllabel/project.json` 里，所以**连续几轮是可比的**。
- `训练 → 实验历史` 汇总所有已记录的轮次（指标、种子、数据集规模、哈希前缀，最新在前），
  并可按 CSV 导出；没有 `run_meta.json` 的旧轮次会以计数形式报告，而不是留空行。
- 数据集构建目录与标签备份都带了时间戳，同一秒内不会互相覆盖；
  旧的副本可以由工具提示回收。

## 5. 溯源信息

每个标注框记录它从哪来：

- `source`：`human` / `model` / `unknown`
- 产出它的模型名
- `model_version`：权重文件的 SHA-1 前缀

于是「这个框是模型画的还是人改的」「它是哪一轮模型画的」都能回答。
`模型产出：…` 会显示在对应位置，重训之后仍然认得出旧框。

悬停信息里能直接看到这些：对象行显示类别、形状、产出模型与权重摘要、置信度、
顶点数、外接框、属性、描述，以及它受什么保护（锁定 / 分组）；
文件行显示路径、标注文件、检查状态与时间，以及当前图片的
模型 / 人工 / 未归属构成。

## 6. 设置与快捷键

设置窗口有四个一级页：**Shortcuts / General / Shape / Canvas**。

- **搜索框**：一次跨所有页匹配，能按配置键、标题、英文描述及其中文译文命中，
  也能按 F1 速查表给出的中文别名命中（输入「撤销」能找到 `shortcuts.undo`）。
  搜索出来的结果保留真实编辑器，可以就地修改，改动会标记**它所属的那一页**为「未保存」。
- **快捷键可以改**：F1 速查表里出现的每一条都能在设置里改键，改完立即生效，不必重启。
- **F1 速查表**：按「快捷键 / 功能 / 分组」分组展示，支持按快捷键或功能名搜索。

## 7. 数据落在哪里

| 内容 | 位置 |
|---|---|
| 项目设置 | `<图片目录>/.jllabel/project.json` |
| 项目索引 | `<工作目录>/.jllabel/projects.json` |
| 标签备份 | `<图片目录>/.label_backups/<时间戳>/` |
| 去重归档 | `<图片目录>._duplicates_archive/` |
| 全局配置 | `~/.xanylabelingrc` |

配置文件（rc）路径与 Python 包名保持上游原样，**没有**跟着改名——改名会同时
牺牲你已有的权重、训练记录和上游可对照性。工具自身版本号显示在窗口标题与状态栏。
