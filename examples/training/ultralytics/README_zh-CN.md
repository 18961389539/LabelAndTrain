# 使用 Ultralytics 训练

[简体中文](README_zh-CN.md) | [English](README.md)

训练面板把当前正在标注的目录变成 YOLO 数据集，在独立进程里训练，并把结果交回自动标注。它覆盖四类任务 —— **检测 / 分割 / 姿态 / 分类** —— 暴露 Ultralytics 训练器约 40 项参数，其中你真正会反复调整的放在前排，其余收在一层折叠之后。

## 开始之前

- **应用必须能导入 ultralytics。** 源码安装：`pip install ultralytics`（或 `uv pip install ultralytics --torch-backend=auto`）。没装时菜单项会给出安装命令而不是打开面板。没有 GPU 的机器可以用 `win-cpu-train` 打包版本：它内置 CPU 版 torch 与 Ultralytics，冻结后的程序也能训练。
- **标注来自本工具。** 数据集由图片旁的同名标签 JSON 构建，这里不读取其它标注格式。
- **所选任务至少需要 20 张有可用标注的图片。** 「数据」页会统计并提示还差几张；"可用"指至少有一个 `矩形`（检测）、`多边形`（分割）、`点`（姿态），或图像级 flag（分类）。
- **姿态任务需要 pose 配置 YAML**（类名 → 关键点名列表），配置页会要求填写，格式见 [`assets/yolov8_pose.yaml`](../../../assets/yolov8_pose.yaml)。

## 闭环

```
标注 → 复核（已检查 / 需返工）→ 仅用「已检查」图片训练
     → best.pt → ONNX → 载入为自动标注模型
     → 全量重推 → 迭代收益看板报告本轮收益
```

训练与重推是刻意分开的两步：面板绝不会背着你改动标注。`用于自动标注` 是一键桥接，并且在执行前询问。

## 1. 数据页

| 控件 | 作用 |
| :--- | :--- |
| 任务类型 | `Classify`、`Detect`、`Segment`、`Pose`，必须选一个；后续向导都随之变化（哪些形状算数、提供哪些预训练权重）。 |
| 有效图片 | `有效图片: N  需要: 20`，达标为绿色、不足为红色，按任务类型缓存。 |
| 数据集摘要 | 标题行（`N 张图 · M 类 · X 已标注 · Y 空标`）加逐类形状计数表，让"少标了一类"在训练前就暴露，而不是等到混淆矩阵。 |
| `加载图片` | 还没打开目录时用它打开（`Ctrl+U`）。 |

空标注不是问题：JSON 里没有形状的图片会作为**背景（负样本）**进入训练集。若不希望它们参与，可在高级设置里勾选「跳过空标注」。

## 2. 配置页

### 基础设置

| 字段 | 说明 |
| :--- | :--- |
| `项目` / `名称` | 运行目录为 `<项目>/<名称>`；项目默认 `<work_dir>/xanylabeling_data/trainer/ultralytics/runs/<task>`。 |
| `模型` | 预训练权重。下拉按当前任务给出常用权重（`yolov8n.pt`、`yolo11s-seg.pt` …）；**填裸文件名即可，首次使用自动下载**，进度显示在训练日志里而不是界面假死；`浏览` 可选择本地 `.pt`。 |
| `数据` | 类别表 YAML。检测/分割/姿态只读取其中的 `names`：面板会按当前目录自动生成（放在训练器 `data/` 目录下，以目录名命名），每次进入配置页刷新，`从标注生成` 可手动刷新；你自己选的 YAML 永不被覆盖。**分类任务可以留空**（数据集由图像 flag 构建），也可以指向预组织好的 `train/ val/ 类别/` 目录。 |
| `姿态配置` | 仅姿态任务：标签转换所用的关键点定义。 |
| `设备` | 按可用性列出 `cuda` / `mps` / `cpu`；有 CUDA 时可勾选具体 GPU。选 **CPU** 时表单会自动适配：AMP 取消并禁用，未修改的 epochs/batch/imgsz 填入 CPU 预置档（50 / 8 / 416），字段下方有说明；你改过的值不会被覆盖。 |
| `训练集比例` | 训练/验证划分（默认 0.8）。划分使用按数据集固定写入 `.jllabel/project.json` 的种子，因此相邻两轮可比。 |

### 参数档位

`快速验证`、`标准`、`高精度` 一键设定训练强度 —— epochs、图片尺寸、patience、close-mosaic 与余弦学习率：

| 档位 | epochs | 图片尺寸 | patience | close_mosaic | 余弦学习率 |
| :--- | ---: | ---: | ---: | ---: | :--- |
| 快速验证 | 30 | 416 | 10 | 5 | 关 |
| 标准 | 100 | 640 | 100 | 10 | 关 |
| 高精度 | 300 | 640 | 100 | 20 | 开 |

档位会覆盖它声明的字段（这正是档位按钮的用途），并把实际填入内容写进日志。`智能推荐参数` 是数据驱动的版本：读取当前目录的类别分布与本数据集的训练历史，填入 epochs / batch / imgsz。

### 基础训练参数

| 字段 | 默认 | 说明 |
| :--- | :--- | :--- |
| `轮数` | 100 | — |
| `批大小` | 16 | `-1` 为自动批次（**仅 GPU 生效**，CPU 上回退为 16）。内存不足时调小。 |
| `图片尺寸` | 640 | 越小越快；CPU 上常用 416。 |
| `进程数` | 8 | 数据加载进程。Ultralytics 在 CPU 上强制为 0；Windows 下 0–2 最稳。 |
| `类别` | 全部 | 参与训练的类别索引，如 `0,1,2`。 |
| `单类别` | 关 | 把所有类别当作同一个类。 |

## 3. 训练页

### 状态与进度

| 状态 | 含义 |
| :--- | :--- |
| `准备就绪` | 空闲。 |
| `准备数据集` | 正在后台线程构建数据集（复制、转换、划分），对话框保持可交互。 |
| `训练进行中` | 训练子进程正在运行。 |
| `训练完成` / `训练失败` | 终态；日志在此时就会落盘。 |

进度条按 `results.csv` 的行数计轮；首轮行出现之前显示 `Starting (elapsed m:ss)`。下方指标行显示最新的 `loss`、`mAP50` 与轮数 —— 从第二轮起还会给出**预计剩余时间**（`预计剩余约 12 分钟`），按最近几轮的节奏估算，因此续训（计时器重启、轮数继续）也能算对。

### 日志

日志视图实时显示训练进程的 stdout/stderr（去掉 ANSI 颜色、上限 10000 行）。**训练完成、失败或被停止时立即写入运行目录的 `logs/`**，而不是只在关窗时写；相同内容不会重复写。`清空` / `复制` 作用于当前视图。

### 训练图片

六个缩略图显示首批训练批次与最新曲线。点击任意一张会打开内置翻页器，覆盖本次运行写出的**全部**图片 —— 所有训练批次、两组验证批次、`results.png`、PR/F1 曲线、混淆矩阵 —— 用 `←`/`→` 或「上一张/下一张」循环翻页，`用系统看图工具打开` 可交给系统看图程序放大。

### 操作

- `打开目录` —— 运行目录。
- `上一步` —— 回到配置页。
- `开始训练` —— 一键启动；数据集准备期间按钮会禁用。
- `停止训练` —— 先确认，再终止整个子进程树。
- `从断点继续` —— 停止后且 `weights/last.pt` 可续训时出现。
- `导出` —— 训练成功后出现。
- `用于自动标注` —— 导出 ONNX 并载入自动标注面板。

### 停止与续训

被停止的运行会保留 `weights/last.pt`（含 epoch 与优化器状态），因此可以接着跑而不是从头再来：

- 训练页的 `从断点继续` 直接继续当前运行。
- 从配置页再次启动时，已存在的运行目录会给出三个选项：**从断点继续**、`使用已训练模型`（导出已有权重）、`重新训练（覆盖）`（破坏性选项，另有确认对话框）。
- 只有真正可续训的断点才会提供续训：跑完所有轮次的运行会被剥离优化器状态，因此正确地不会出现该选项。
- 续训时 Ultralytics 会**从断点恢复**项目、轮数与全部超参；设备仍可更换（换机器时很有用），数据集会按固定划分种子重建并以 data 覆盖参数传入，因此即使旧数据集副本被清理也不影响续训。
- 续训会忽略配置页对 epochs/batch/imgsz 的改动，运行开始时日志会说明这一点。

### 训练失败时

对话框会翻译出错原因（Windows 退出码会被转换成可读说明），当原因有对策时，把对策作为默认按钮给出：

| 现象 | 按钮 | 实际改动 |
| :--- | :--- | :--- |
| 内存/显存不足（OOM） | `批大小减半并重试` | 批大小减半（原为 `-1` 时落到 8） |
| 退出码 `-1073741819` / `-1073740940`（访问违例 / 堆损坏） | `Workers 设为 0 并重试` | 进程数 → 0 |
| 无可用 CUDA 设备 | `改用 CPU 并重试` | 设备 → cpu（并触发上面的 CPU 适配） |

`重试训练`（原样重试）与 `返回配置` 始终存在。修复会先写入表单并记入日志，然后才开始重试；完整 traceback 保留在日志视图中。

## 产物

```
<work_dir>/xanylabeling_data/trainer/ultralytics/
├── weights/                       预训练权重下载缓存
├── data/                          自动生成的类别表 YAML
├── datasets/<task>/<name>_<stamp>/    每次训练一份构建
│   ├── images/{train,val}/  labels/{train,val}/   （Windows 复制，其它平台软链接）
│   ├── data.yaml                   Ultralytics 实际读取的文件
│   └── manifest.json               每个标签文件及其内容哈希、划分、类别表、种子
└── runs/<task>/<name>/
    ├── weights/best.pt、last.pt
    ├── results.csv                 进度与指标来源
    ├── args.yaml                   本次运行的完整参数
    ├── 图表（PR/F1 曲线、混淆矩阵、批次样例 —— 开启时）
    ├── logs/training_log_<状态>_<时间戳>.txt
    └── run_meta.json               权重哈希、训练参数、数据集 manifest 哈希与计数、指标
```

训练结束后面板可能提示清理历史数据集副本 —— 它们是完整的图片副本，不清理目录只会越来越大。最近 5 份以及本次运行所用的那一份一定会保留，且只有候选超过 100 MB 时才会询问。

## 导出

`导出` 可把运行的 `best.pt` 导出为 14 种格式：ONNX、TorchScript、OpenVINO、TensorRT、CoreML、TensorFlow SavedModel / Lite / Edge TPU / TF.js、PaddlePaddle、MNN、NCNN、IMX500、RKNN（部分格式需要额外依赖，对话框会提示）。

`用于自动标注` 是闭合闭环的快捷方式：把 ONNX 导出到模型旁的 `weights/`，写出面板需要的模型 YAML（名称、类别 —— 姿态任务复用训练时的关键点映射 —— 以及 0.25 的置信度阈值；分类任务用 0.0，避免 top-k 建议被阈值过滤掉），载入为固定不被淘汰的自定义模型，然后询问是否重新推理整个目录。重推会跳过「已确认的空标注」（负样本），完成后「迭代收益看板」会更新本轮的收益。

## 实验历史

`训练 → 实验历史` 列出所有写出 `run_meta.json` 的运行：指标、种子、数据量、迭代轮次、权重与 manifest 哈希、时间，按完成时间倒序，支持导出 CSV 与"打开该运行目录"。训练到自定义 `项目` 路径下的运行不在扫描范围内，对话框会说明它扫描的是哪个目录。

## 纯 CPU 训练

以上功能在没有 GPU 的机器上全部可用，只是每轮更慢：

- 表单会把 AMP 关掉，并在你未修改相关字段时填入 CPU 预置档（50 轮 / 416 / 批大小 8），让第一轮能在可接受的时间内告诉你数据是否有问题。
- Ultralytics 在 CPU 上会强制把数据加载进程设为 0，`进程数` 保持默认即可。
- `win-cpu-train` 打包（`scripts/build_executable.sh win-cpu-train`，spec 为 `packaging/pyinstaller/specs/x-anylabeling-win-cpu-train.spec`）内置 CPU 版 torch 与 Ultralytics，适合完全没有 CUDA 的机器。

## 常见问题

| 现象 | 处理 |
| :--- | :--- |
| 菜单提示缺少 Ultralytics | 在应用所用环境执行 `pip install ultralytics`（或 `uv pip install ultralytics --torch-backend=auto`）；`win-cpu-train` 冻结版本已内置。 |
| 出现「批大小减半并重试」 | 训练内存/显存不足 —— 接受即可，或自行调小 `批大小` / `图片尺寸`。 |
| 子进程以访问违例崩溃 | 接受「Workers 设为 0 并重试」，或改用 CPU。 |
| 进度长时间停在 0/N | 首轮最慢（加载模型、构建缓存）；进度条先显示已用时间，之后切换为轮数，可看日志确认确实在推进。 |
| 跑完之后没有「从断点继续」 | 完整跑完的运行会剥离优化器状态，没有可续的东西 —— 直接开始新一轮训练。 |
| 新一轮把我的旧运行覆盖了 | `重新训练（覆盖）` 会删除运行目录（确认框会列出其中的内容）。想保留两份请改 `名称`。 |
| 训练跑到了错误的 GPU | 在 `设备` 旁勾选 GPU；多卡机器默认全部勾选。 |
